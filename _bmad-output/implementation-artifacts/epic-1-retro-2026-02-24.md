## 做得好的（Successes）

### 1. VFSError 模式确立——全项目错误处理标准

Story 1-3 确立的 `VFSError` 模式成为后续所有模块的错误类型模板（`ContextError`、`SyscallError`）。保持了依赖方向干净，每个层定义自己的错误类型而非反向导入。

### 2. TOCTOU 意识和原子操作

Story 1-3 发现并修复了 `Close` 方法的 TOCTOU 竞态，引入 `LoadAndDelete` 原子操作模式。此后每个涉及并发的 Story（1-4、1-5、1-6、1-7、1-8）都自觉应用了这个模式。

### 3. CommandBuilder 注入——exec.Command 可测试性

Story 1-5 引入的 `CommandBuilder` 函数类型注入模式，解决了 `exec.Command` 难以测试的问题。Story 1-8 的 `claudeVersionChecker` 复用了同样思路。

### 4. KernelCallbacks 接口——干净的层间解耦

Story 1-7 设计的 `KernelCallbacks` 接口实现了内核与 UI 的干净分离。内核不知道 UI 的存在，通过回调通知进度，CLI 层负责渲染。

### 5. 全面的测试基础设施

200+ 测试函数覆盖了从单元测试到 E2E 集成测试的完整光谱，全部通过 `-race` 竞态检测。`newTestKernel` 等 mock 基础设施可复用。

### 6. 代码审查质量

每个 Story 的代码审查都发现了 HIGH 级别问题并完成修复。审查是质量的最后一道防线。

## 挑战和问题（Challenges）

### 1. 测试覆盖盲区——每个 Story 都有

**频率：** 8/8 个 Story（100%）

每个 Story 的代码审查都发现了未覆盖的测试场景，说明开发阶段的测试思维需要加强。常见遗漏：边界条件、并发路径、错误路径。

### 2. 并发安全问题反复出现

**频率：** 5/8 个 Story

- Story 1-2：`GetState()` 需要线程安全读取器
- Story 1-3：`Close` TOCTOU 竞态、`fdTables` 改为 `SyncMap`
- Story 1-5：`Stream` goroutine 需要 `cmd.Wait()`
- Story 1-7：`.gitignore` 导致 `cmd/crux/` 目录被忽略
- Story 1-8：`syncWriter` 替代 `bytes.Buffer` 解决回调写入竞态

### 3. 全 mock 测试的根本局限

**严重度：** HIGH

真实环境验收暴露了 mock 测试无法发现的问题：

- Claude CLI exit code 1 时 stdout JSON 未被解析，错误信息丢失
- `--max-turns 1` 语义假设与真实 CLI 行为不符（CLI 内部有自己的工具循环）
- `result` 字段在 max_turns 截断时缺失，未做 graceful fallback

### 4. API 签名演进的连锁影响

Story 1-6 → 1-7 的 `NewKernel` 签名变更（新增 `callbacks` 参数）导致所有已有测试需要更新。跨 Story 的 API 演进需要更好的前瞻规划。

## 关键洞察（Key Insights）

1. **代码审查是质量保障的核心环节** — 每个 Story 都靠审查发现了关键问题。在 AI 辅助开发中，审查的重要性不减反增。

2. **全 mock 测试能保证逻辑正确，但无法发现集成层语义问题** — 架构假设需要用真实环境验证。mock 测试和集成测试是互补的，不能互相替代。

3. **好的模式会自然传播** — VFSError → ContextError、TOCTOU → LoadAndDelete、CommandBuilder → claudeVersionChecker。在早期 Story 建立好的模式，后续团队会自觉复用。

4. **并发安全需要系统性思维** — 不能靠事后修复，需要在设计阶段就识别所有共享状态和竞争条件。

## 回顾结论

Epic 1 成功交付了 Crux Agent OS 的核心骨架——从进程模型、VFS、上下文管理到 LLM 驱动和 CLI 入口，8 个 Story 全部完成。200+ 测试函数和全面的代码审查保证了代码质量。

真实环境验收揭示了 3 个 HIGH 级别的驱动层集成问题，这些是全 mock 测试固有盲区的直接后果。团队决定在进入 Epic 2 前修复这些问题。

**核心经验：** mock 测试保证逻辑正确，但架构假设必须用真实环境验证。好的模式会自然传播，而并发安全需要从设计阶段就系统性地处理。
