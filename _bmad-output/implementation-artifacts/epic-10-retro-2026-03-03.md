### 2. Supervisor 作为 kernel Process 的架构决策

Supervisor 不是独立的管理实体，而是普通的 kernel Process，运行 `supervisorLoop` 而非 `reasonStep`。这意味着 rnix top、rnix ps、kill、strace 自动适用，零额外集成代码。直接借鉴 Erlang/OTP 的 Supervisor 行为模块，三种重启策略 + 滑动窗口风暴保护。

## 挑战和问题（Challenges）

### 1. Story 10.4 CR-1 CRITICAL：Stale Exit Event 级联误重启

在 one_for_all 和 rest_for_one 策略下，旧 monitor goroutine 的陈旧退出事件被误归因给新重启的子进程，导致级联误重启直到风暴保护介入。

修复：`childExit` 结构体添加 `pid` 字段，`handleChildExit` 验证 PID 匹配当前子进程，不匹配则丢弃。

教训：并发系统中，channel 消费者必须验证消息的时效性和身份。

### 2. Deferred Items 持续积累

Epic 10 新增约 7 个 deferred items：
- 10.5 H2: checkSupervisorStartup 200ms 硬编码超时
- 10.5 H3: serviceRegistry 全局可变状态
- 10.5 M3: TestBootstrap 不直接断言 Agent 字段
- 10.5 M5: 内置服务仅测试容错路径
- 10.3: 3 个 LOW 级别问题

加上从 Epic 2-9 遗留的技术债，总量在增长。但 Epic 10 主动清理了 Epic 9 的 5 个高优先级债务，进入速度在放缓。

### 3. SpawnSupervisor 异步启动检测的 Workaround

Story 10.5 中 `checkSupervisorStartup` 使用 200ms 超时 heuristic 来检测异步启动失败。正确方案是让 SpawnSupervisor 返回 ready channel，但需要更大的 API 变更。当前 workaround 在 MVP 阶段可接受。

### 4. LOW 自检步骤仍需加强

Epic 9 的第 6 个 Action Item（开发完成后增加收尾自检）部分执行。10.5 仍有 4 个 deferred items，其中部分本可以在提交前自检时发现。但对比 Epic 9，LOW 问题并未继续上升，算是稳住了。

## 关键洞察（Key Insights）

1. **新概念应该组合现有概念，而非创建全新抽象** — Supervisor = Process + 监控循环。rnix top、rnix ps、kill 自动适用，零集成成本。

2. **channel 消费者必须验证消息身份（PID/序列号/时间戳）** — CR-1 CRITICAL bug 证明：goroutine + channel 架构中，"陈旧消息" 是隐蔽的攻击面。

3. **改进项的半衰期极短——回顾后立即执行** — 连续 4 个 Epic 验证：Action Items 从 14% 跃升到 83%，唯一变量是"当场执行"而非"推迟"。

4. **Dev Notes 显式列出复用清单，将隐性知识显性化** — 跨 Story 模式复用链是 Epic 10 速度的关键倍增器。

5. **新框架引入时详细记录 Debug Log** — bubbletea v2 API 差异、stopChild wg.Wait() 替代方案、异步启动检测 workaround——这些记录将持续产生价值。

## 回顾结论

Epic 10 是 Rnix 项目实现生产级运维能力的里程碑。5 个 Story 全部完成，100% 交付率，连续第三个 Epic 全量交付。

**核心成就：**
- rnix top（bubbletea v2 TUI）和 rnix log（三段式分类日志）为用户提供了完整的运维可观测性
- Token 预算管理实现了 LLM 成本控制的闭环（Agent 配置 → Compose 覆盖 → 内核执行 → rnix top 可视化）
- Erlang/OTP 风格 Supervisor 树让多智能体系统具备了容错能力
- 配置驱动的 init 引导序列完成了 daemon 启动的最后一块拼图

**最显著的改善：** Action Items 完成率从 14%（Epic 9）跃升到 83%（Epic 10），核心驱动因素是"回顾后立即执行"的决定。

**最有价值的发现：** Story 10.4 Code Review 中的 CR-1 CRITICAL bug（stale exit event 级联误重启），证明了 Code Review 在并发系统中的不可替代价值。

**下一步：** 修复 pipeBuffer 无界增长（CRITICAL 前置），验证 Pipe 对管道语法的适用性，然后启动 Epic 11（AgentShell 高级语法）。
