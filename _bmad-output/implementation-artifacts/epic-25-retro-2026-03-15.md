### 业务成果

Epic 25 将 Rnix 从"固定目录结构的开发工具"升级为"用户可定制的配置化系统"。用户通过 `rnix init` 一条命令即可创建完整的全局配置环境（`~/.config/rnix/`），内置 agent/skill 从二进制自动提取并可自由修改。项目中创建 `.rnix/` 后，项目级配置自动与全局 deep merge，项目级 agent/skill shadow 全局同名定义。同一 daemon 同时服务多项目，每进程持有不可变配置快照。

**基础设施建立（25.1）：** 在 `internal/config/` 包中建立双层配置路径解析、YAML 深度合并、Shadow 遮蔽查找和 embed.FS 嵌入提取能力。config 包仅依赖标准库，文件级职责严格隔离（paths.go 纯路径、merge.go 纯数据结构、embed.go 纯文件操作）。项目根 `embedded.go` 通过 `//go:embed` 将 `lib/agents/` 和 `lib/skills/` 嵌入二进制。

**CLI 与 Daemon 改造（25.2）：** `rnix init` 单一入口自动判断全局/项目初始化，从 embed.FS 提取内置资源，生成默认配置。`runDaemon()` 全量改造——所有硬编码路径（`"lib/agents"`、`"lib/skills"`、CWD 相对路径）替换为 `config.GlobalDir()` 派生路径。运行时数据迁移到 `.rnix/data/` 子目录。

**跨模块适配（25.3）：** IPC SpawnRequest 新增 ProjectDir 字段，CLI 自动发现 `.rnix/` 并传入 daemon。daemon 端 `resolveProjectContext()` 实现项目配置合并，创建项目感知的 AgentLoader 和 SkillLoader。agents、skills、kernel、compose 等 6 个包完成多目录适配。

## 成功与优势

1. **"Foundation → Consumer → Adapter"三层递进模式——3 个 Story 完美协作** — 25.1 创建纯库 API → 25.2 用 API 构建 CLI 和 daemon 加载 → 25.3 将 API 注入到现有模块。每个 Story 的输入是上一个 Story 的输出，依赖链极其清晰。这种模式避免了"一次性大改"的风险，同时保证了每个 Story 都有可编译、可测试的交付件。

2. **internal/config 包的架构隔离——零外部依赖** — config 包仅依赖 Go 标准库（io/fs, maps, os, path/filepath, sort），不导入项目内任何包。这使得它可以被所有上层模块安全引用，不存在循环依赖风险。文件级职责隔离（paths.go 纯路径计算、merge.go 纯数据结构操作、embed.go 纯文件操作）进一步增强了可维护性。config 包是 Rnix 项目中隔离度最高的包之一。

3. **ShadowResolve——简洁而强大的抽象** — 一个 10 行函数（按目录优先级遍历 + os.Stat）统一解决了 agent 和 skill 的双层查找问题。agents/loader.go 和 skills/loader.go 的改造只需将 `basePath string` 改为 `searchDirs []string` + 一行 `config.ShadowResolve` 调用。小函数大价值——与 Epic 24 的 `parseModel` 函数异曲同工。

4. **embed.FS——从"运行时依赖目录"到"自包含二进制"** — 通过 `//go:embed`，内置 agent/skill 成为二进制的一部分。`rnix init` 提取到用户目录后用户可自由修改——"开箱即用 + 可定制"双重目标达成。测试中使用 `testing/fstest.MapFS` 替代真实 embed.FS，实现了完美的测试隔离。

5. **Code Review 发现真实集成遗漏** — 25.3 的审查发现 `handleSpawnPipeline` 和 `handleExecScript` 未使用 `resolveProjectContext`，直接绕过项目级配置。这是 HIGH 级缺陷——pipeline 和 script 场景下项目级 agent/skill 不会生效。审查中新增 `ipcKernelSpawner.projectConfig` 字段并修复了两个 handler。Code Review 在"跨模块适配"场景中的价值再次验证。

6. **完成速度极快——3 个 Story 单日完成** — 原因分析：(a) Epic 25 的设计简报（Party Mode 讨论产出）提供了完整架构决策；(b) 25.1 的 API 设计极其明确；(c) 修改的代码大部分是"路径替换"而非新逻辑；(d) 零外部依赖消除了第三方集成问题。

7. **向后兼容性精心处理** — daemon 全局配置目录不存在时降级使用默认配置（不崩溃）；`rnix-init.yaml`/`init.yaml` 双路径兼容；`.rnix/records` → `.rnix/data/records` 保持旧路径回退；旧版 CLI 不发送 ProjectDir 时 daemon 按空处理（omitempty）。

## 挑战与成长领域

1. **25.2 的 ATDD 测试差距——runDaemon() 可测试性瓶颈** — ATDD 规划 31 个测试，实际实现 16 个。差距集中在 daemon 配置加载场景（AC5-7），因 `runDaemon()` 深度集成 IPC 服务器，无法隔离测试。通过提取 `resolveDataDir()` 和 `loadInitConfigCompat()` 辅助函数分别测试，达到合理但不完美的覆盖。这是长期存在的架构问题：`runDaemon()` 承担太多职责。

2. **25.3 的修改面广泛——27 个文件 blast radius** — 修改了 ipc、agents、skills、kernel、cmd/rnix、drivers/llm 共 6 个包的 27 个文件。虽然大部分是参数类型变更（`string` → `[]string`），但广泛改动增加了回归风险和审查难度。全项目 21 个包的测试通过证明了测试套件的强度。

3. **resolveProjectContext MCP 配置 nil——已知功能缺口** — 项目级 AgentLoader 创建时 mcpCfg 传 nil，项目级 agent 引用 MCP server 会报错。LOW 级但明确的功能缺口。

4. **filepath.Join vs 字符串拼接——反复出现** — 25.2 的 `resolveDataDir()` 使用字符串拼接 `cwd + "/.rnix/" + name`，CR 修复为 `filepath.Join`。此问题在 Epic 20 也出现过。反复出现说明需要自动化防护。

5. **25.1 ATDD 测试规划实现不对齐** — 规划 38 个测试但初始只实现 31 个，CR 补充了缺失的 9 个。测试规划与实现的对齐是 ATDD 核心价值——规划了但不实现等于没规划。

## 关键洞察

1. **"纯函数库 + 消费者"是最干净的 Epic 结构** — 25.1 的 config 包是纯函数库（无全局状态、无 I/O 副作用），25.2/25.3 是消费者。(a) 25.1 可独立测试（40 个测试无需 mock）；(b) 25.2/25.3 只需验证"是否正确调用 config API"；(c) 未来任何模块可安全引入 config 包。建议未来"基础设施类 Epic"都采用此模式。

2. **embed.FS + fs.FS 接口——Go 内置资源分发最优解** — 无需额外工具，编译器原生支持。`testing/fstest.MapFS` 提供完美测试替身。`ExtractEmbedded` 接受 `fs.FS` 接口而非具体 `embed.FS` 类型，实现了测试与实现的解耦。

3. **"双层配置 + Shadow 遮蔽"是 Unix 哲学现代复刻** — 全局 `~/.config/rnix/` + 项目 `.rnix/`，DeepMerge 用于配置文件（递归 map 合并），Shadow 用于资源目录（整体遮蔽不合并）。两种策略各有适用场景，设计选择正确。

4. **跨模块适配场景中 Code Review 价值最高** — 25.3 的 HIGH 缺陷是典型的"改了主路径遗漏分支路径"。Code Review 的系统性扫描比开发者逐点修改更可靠。

5. **延续行动项需要清理机制** — 从 Epic 14 至今积累了 13 个延续行动项，其中 5 个连续 4+ 个 Epic 未触发。反复抄写不触发的行动项浪费审查时间。建议：连续 4 个 Epic 未触发的行动项归档，仅保留跨领域适用的。

### 团队协议

- **配置路径禁止硬编码**：所有配置路径必须通过 `config.GlobalDir()`、`config.ProjectDir()`、`config.ResolvePath()` 获取
- **embed.FS 内置资源分发**：agent/skill 通过 embed.FS 嵌入二进制，`rnix init` 提取到用户目录
- **双层配置体系**：全局 `~/.config/rnix/` + 项目 `.rnix/`，DeepMerge 用于配置文件，Shadow 用于资源目录
- **ProjectConfig 不可变**：spawn 时创建快照，进程生命周期内不修改
- **延续行动项清理**：连续 4+ 个 Epic 未触发的归档，不再逐次抄写
- ATDD 测试先行继续作为标准开发流程
- 所有测试启用 `-race`
- 统一使用 Claude Opus 4.6 开发
- Code Review 在跨模块适配场景中执行系统性扫描
