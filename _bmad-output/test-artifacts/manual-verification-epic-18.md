# Epic 18 手工验证指南：AgentShell 完整脚本语言

## 概述

本文档提供 Epic 18 所有 Story 的手工验证步骤，用于在自动化测试之外对功能进行端到端的人工确认。

## 前置准备

AgentShell 脚本通过 `rnix run` 执行或在交互模式中使用。Daemon 由 rnix 自动按需启动。

```bash
# 1. 构建最新版本
make build

# 2. 准备测试脚本目录
mkdir -p /tmp/ash-tests

# 3. 准备一个基本测试脚本
cat > /tmp/ash-tests/hello.ash << 'EOF'
#!/usr/bin/env rnix run
spawn "向用户打招呼" --agent=greeter
EOF
chmod +x /tmp/ash-tests/hello.ash

# 4. 准备一个辅助库脚本（用于 source 测试）
cat > /tmp/ash-tests/helpers.ash << 'EOF'
fn greet(name)
  spawn "向 ${name} 打招呼" --agent=greeter
end

fn analyze(file)
  spawn "分析 ${file} 的代码质量" --agent=analyst
end
EOF
```

> **提示**：脚本执行需要 daemon 运行（通过 IPC spawn agent）。解析和语法验证不需要 daemon。

## 关键注意事项

1. **脚本执行需要 daemon** — spawn 通过 IPC 调用 daemon 创建智能体
2. **关键字大小写不敏感** — `for`/`FOR`/`For`、`while`/`WHILE` 等均可
3. **NFR38** — 脚本解析时间 <= 50ms（含 source 展开，<= 1000 行）
4. **NFR39** — 循环/函数调用运行时开销 <= 1ms/次
5. **无限循环保护** — while 循环超过 10000 次迭代自动中断
6. **递归深度保护** — 函数调用超过 100 层自动报错
7. **parallel 块限制** — 块内只允许 spawn 和 pipeline，不允许 if/for/export 等
8. **parallel 容错** — 一个 spawn 失败不影响其他，块结束后汇总所有结果
9. **source 循环引用** — 使用绝对路径检测，`./a.ash` 和 `a.ash` 被视为同一文件
10. **变量作用域** — for 循环变量循环后清除，函数参数函数返回后恢复
11. **字符串插值严格模式** — spawn intent 中引用未定义变量将报错（非静默展开为空）
12. **shebang** — 首行 `#!/usr/bin/env rnix run` 在解析和 source 时自动跳过
