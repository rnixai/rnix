# Epic 19 手工验证指南：声明式意图与自动规划

## 概述

本文档提供 Epic 19 所有 Story 的手工验证步骤，用于在自动化测试之外对功能进行端到端的人工确认。

## 前置准备

Daemon 由 rnix 自动按需启动（`EnsureDaemon`），无需手动管理。

```bash
# 1. 构建最新版本
make build

# 2. 确认 daemon 可用
./rnix ps
```

> **提示**：`rnix apply` 和 `rnix intent status` 需要 daemon 运行（通过 IPC 通信）。意图分解过程会调用 Claude Code CLI 进行 LLM 推理。

## Story 19.2: 意图状态模型与事件驱动 Reconciler

### 三态模型（Desired/Current/Drift）

| # | 验证场景 | 操作步骤 | 预期结果 | 通过 |
|---|---------|---------|---------|------|
| 1 | Desired 初始化 | 提交意图并确认执行，查询状态 | 所有节点的 desired 状态为 `completed` | [ ] |
| 2 | Current 更新 | 在执行过程中查询状态 | 各节点 Current 状态反映实际执行进度（pending/executing/completed） | [ ] |
| 3 | Drift 检测 | 制造一个子任务失败的场景（如 agent 超时），查询状态 | 状态信息中包含 drift 项列表，标注 drift 类型（node_failed 或 node_timeout） | [ ] |

### 自动重试

| # | 验证场景 | 操作步骤 | 预期结果 | 通过 |
|---|---------|---------|---------|------|
| 4 | 失败后自动重试 | 提交意图使某子任务首次失败但后续成功 | CLI 显示重试事件：`retrying node <id> (attempt N/M)`，最终该节点标记为 completed | [ ] |
| 5 | 重试耗尽 | 使某子任务持续失败 | 重试次数达上限后（默认 3 次），节点标记为最终 failed，依赖下游级联失败 | [ ] |
| 6 | 重试不影响独立分支 | 并行节点中一个节点重试，另一个正常完成 | 正常节点不受重试节点影响，独立完成 | [ ] |

### 超时处理

| # | 验证场景 | 操作步骤 | 预期结果 | 通过 |
|---|---------|---------|---------|------|
| 7 | 节点超时 | 提交一个耗时较长的子任务（配置较短的超时） | CLI 显示超时事件，超时后按重试策略处理 | [ ] |
| 8 | 超时后重试成功 | 超时后重试并成功完成 | 节点最终标记为 completed，drift 清除 | [ ] |

### NFR40 延迟验证

## Story 19.3: 增量更新与状态查询

### 增量更新基本流程

| # | 验证场景 | 操作步骤 | 预期结果 | 通过 |
|---|---------|---------|---------|------|
| 1 | 增量更新 | 先 `rnix apply "博客系统"` 执行，待部分完成后 `rnix apply "加上评论功能" --update <intent-id>` | Reconciler 计算增量差异，显示新增节点和修改节点列表，仅执行新增/变更部分 | [ ] |
| 2 | 已完成工作不回滚 | 增量更新后查询状态 | 已完成的子任务保持 completed 状态，不被重置 | [ ] |
| 3 | 新节点依赖已完成节点 | 增量更新添加的新节点依赖已完成的上游节点 | 新节点立即可调度执行，无需重新执行上游 | [ ] |
| 4 | 新节点依赖未完成节点 | 增量更新添加的新节点依赖尚在执行中的节点 | 新节点等待依赖完成后自动调度 | [ ] |
| 5 | 修改已完成节点意图 | 增量更新修改了已完成节点的意图描述 | 该节点被重置为 pending，重新执行 | [ ] |

## 关键注意事项

1. **意图分解需要 LLM** -- `rnix apply` 通过 Claude Code CLI 调用 LLM 进行意图分解，需要 Claude CLI 可用
2. **Daemon 必须运行** -- 所有命令通过 IPC 与 daemon 通信，daemon 由 `EnsureDaemon` 自动管理
3. **Intent ID 格式** -- ID 为 `intent-N` 格式（递增数字），daemon 重启后从 1 重新计数
4. **DAG 执行顺序** -- 子任务按 DAG 拓扑排序执行，无依赖的并行，有依赖的串行
5. **Reconciler 默认配置** -- 最大重试 3 次，默认超时 5 分钟，调和间隔 1 秒
6. **NFR40** -- Reconciler 从检测到 drift 到启动调和行动延迟 <= 5s
7. **退出码** -- `rnix apply` 有失败子任务时退出码非零
8. **增量更新** -- `--update` flag 指定目标 intent ID，LLM 基于现有子任务状态做增量分解
9. **三态模型** -- Desired（目标全部 completed）、Current（各节点实际状态）、Drift（差异列表）
10. **意图仅内存存储** -- daemon 重启后意图数据丢失
